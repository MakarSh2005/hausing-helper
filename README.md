# Жилищный помощник

Бот для мессенджера MAX: жилец привязывает квартиру, подаёт заявку, а бот сам определяет ответственную организацию и следит за сроком ответа. Хакатон MAX, трек «Умный город».

> Этот README рабочий и описывает этапы 1–8. Полная версия по 15 пунктам формата сдачи пишется на этапе 11.

## Запуск на своём компьютере через VS Code (без Docker и без домена)

Нужны [Node.js LTS](https://nodejs.org) и VS Code. Бот работает в режиме `MAX_MODE=polling`: сам забирает сообщения у MAX, поэтому HTTPS и вебхук не нужны. Бот отвечает, только пока запущен.

1. VS Code → File → Open Folder… → папка `housing-helper`.
2. Terminal → Run Task… → **«1. Подготовить проект (один раз)»**. Создаст `.env`, поставит зависимости и базу.
3. Открыть `.env` в корне и вписать токен после `MAX_BOT_TOKEN=`.
4. Terminal → Run Task… → **«2. Запустить бота»** (или F5 — запуск с отладчиком).
5. Написать боту в MAX.

## Запуск через Docker

```bash
git clone <репозиторий> housing-helper && cd housing-helper
cp .env.example .env        # вписать MAX_BOT_TOKEN
docker compose up --build
```

Поднимается один контейнер — тот же образ, что на хостинге: миграции → seed справочников → бот. Проверка: http://localhost:3000/health → `{"status":"ok"}`, мини-приложение — http://localhost:3000/app/ (вне MAX покажет «Откройте из чата с ботом» — так и должно быть).

Локально бот работает в режиме `MAX_MODE=polling`: сам забирает сообщения, HTTPS и домен не нужны. **Важно:** у рабочего бота активна подписка на вебхук, и пока она есть, MAX не отдаёт события через polling — локальный контейнер с тем же токеном запустится, но сообщений не получит (в логе будет предупреждение). Для локальной отладки нужен отдельный тестовый бот. Не снимайте подписку рабочего бота (`npm run unsubscribe`) — он перестанет отвечать жюри.

БД лежит в томе `app-data` (`/data/app.db`) и переживает `docker compose down && docker compose up`. Полный сброс: `docker compose down -v`.

## Деплой на хостинг без консоли (Amvera)

`Dockerfile` и `amvera.yml` в корне собирают один контейнер: при старте применяются миграции, seed и запускается бот. База лежит в `/data`. При `MAX_AUTO_SUBSCRIBE=true` бот сам оформляет подписку на `PUBLIC_BASE_URL/webhook`. Пошаговая инструкция — в документе «Деплой бота на хостинг без консоли».

## Локальная разработка

```bash
cp .env.example .env          # в корне репозитория; заполнить секреты
cd backend
npm install
npm run db:generate           # Prisma Client
npm run db:check              # сверка миграции со схемой (см. «Что проверить»)
npm run db:deploy             # применить миграции
npm run db:seed               # заполнить справочники
npm run dev                   # сервер с перезапуском на изменения
npm test                      # тесты
```

Все скрипты читают единый `../.env` через `node --env-file`.

## Подключение к MAX

1. Бэкенд должен быть доступен снаружи по `https://` с сертификатом от доверенного центра. Самоподписанные сертификаты и HTTP MAX не принимает.
2. В `.env` указать `PUBLIC_BASE_URL`.
3. `npm run subscribe`: скрипт проверит `/health`, токен (`GET /me`), создаст подписку на `message_created`, `bot_started`, `message_callback` и сверит результат через `GET /subscriptions`.
4. `npm run subscriptions` — список подписок, `npm run unsubscribe` — удалить.

Чтобы сверить реальный формат событий с ТЗ 5.1, временно включите `LOG_RAW_UPDATES=true` и `LOG_LEVEL=debug`. После сверки обязательно выключите: в сырых событиях есть тексты пользователей.

## Вебхук: поведение

| Ситуация | Ответ |
|---|---|
| Нет или неверный `X-Max-Bot-Api-Secret` | `401`, тело не разбирается |
| Верный секрет | `200 {"ok":true}` сразу, обработка после ответа |
| Верный секрет, битый JSON | `200` + предупреждение в логе (MAX не должен ретраить) |
| Повторная доставка | `200`, обработчик не вызывается повторно |
| Ненужный тип события | `200`, молча игнорируется |
| Форма события не совпала со схемой | `200`, в логе пути полей (без значений) |
| > 100 событий/мин от одного user_id | `200`, событие отбрасывается с предупреждением |

Ключи идемпотентности: `msg:<mid>`, `cb:<callback_id>`, `start:<user_id>:<timestamp>`. У `bot_started` нет `mid`, поэтому ключ собран из пользователя и времени. Записи старше суток удаляются раз в час.

## Справочник домов

Источник — `backend/prisma/reference/kazan-houses.json`: 263 домов в Авиастроительном, Вахитовском, Кировском и Московском районах Казани, 4 управляющие компании. Данные собраны 25.09.2026 из ГИС ЖКХ, ЕГРЮЛ и сайтов УК. Файл делает скрипт из Excel-шаблона:

```bash
python3 tools/import_houses.py Справочник-домов-Казани.xlsx --verified   # данные сверены: бот покажет телефоны УК
python3 tools/import_houses.py Справочник-домов-Казани.xlsx              # УК помечаются «данные уточняются»
```

Скрипт оставляет в ИНН только цифры (при копировании с сайтов в ячейку попадают невидимые символы), переносит корпус из столбца «Дом» («15 корпус 1») в свой столбец, пропускает строки без номера дома и сообщает обо всём этом. Телефоны УК бот показывает, только если справочник отмечен как проверенный **и** ИНН проходит проверку контрольной цифры.

Seed загружает справочник при каждом старте и заменяет прежний: дома и УК, которых нет в файле, удаляются, кроме тех, к которым уже привязаны квартиры или заявки жильцов. `test/reference.test.ts` проверяет, что каждый дом находится по адресу в двух написаниях.

Номера с дробью («13/6») бот понимает и как угловой дом целиком, и как «дом 13, корпус 6» — в зависимости от того, что есть в справочнике.

Диплинк на дом: `https://max.ru/t186_hakaton_max_bot?start=<код дома>`, например `?start=kzn_0078` — пр-кт Ибрагимова, 12. Коды — в `kazan-houses.json`, при повторном импорте сохраняются.

## Как устроен сервис

**Чат-бот — входная дверь.** Жилец пишет адрес, бот проверяет его по справочнику и прямо говорит, нашёл ли дом. Дальше — номер квартиры и подъезд. После привязки у жильца ровно две кнопки: **«Приложение с заявками»** (запускает мини-приложение внутри MAX) и **«Сменить адрес»** (прежний адрес остаётся, пока не привязан новый). На любое другое сообщение бот напоминает, что заявки подаются в приложении, и показывает те же две кнопки.

Бот пишет сам в двух случаях: на «запах газа» — сразу памятка с 104 и 112 (сюда нельзя отправлять в приложение), и когда истёк срок по заявке — напоминание с кнопкой «Открыть заявку» (мини-приложение не умеет присылать уведомления).

**Мини-приложение — всё остальное:** подача заявки (описание, категория — определяется сама, её можно сменить, до 5 фото с телефона), список и карточка заявки, отзыв, «Проблема решена», «Не решена» — готовый текст жалобы в ГЖИ РТ с кнопкой «Скопировать», данные квартиры и УК.

## Заявка

Перед отправкой видно, кто отвечает и какой срок реакции установлен нормативом. После отправки — номер `REQ-ГГГГ-NNNNN` и срок «до ДД.ММ, ЧЧ:ММ (МСК)».

| Категория | Кто отвечает | Срок | Основание |
|---|---|---|---|
| Отопление, вода, электричество | УК | проверка — 2 ч, устранение аварии — до 3 суток | п. 108 Правил № 354, п. 13 Правил № 416 |
| Канализация, засор | УК | 2 ч | п. 13 Правил № 416 |
| Крыша, лифт, двери и стёкла в подъезде | УК | 1 сутки | прил. 2 к Правилам № 170 |
| Свет в подъезде | УК | 7 суток | прил. 2 к Правилам № 170 |
| Вывоз мусора | региональный оператор ТКО | перерыв не более 24 ч | прил. 1 к Правилам № 354, п. 17 |
| Двор, другое | УК | ответ — 10 рабочих дней | п. 36 Правил № 416 |
| Запах газа | — | заявка не оформляется: памятка и 104 / 112 | — |

Источник сроков один — `backend/src/domain/norms.ts`; логика подачи — `backend/src/requests/service.ts`.

**Фото.** Мини-приложение сжимает фото до 1600 px и загружает их по одному после создания заявки: заявка не теряется, даже если какое-то фото не дошло (его можно добавить в карточке). Сервер определяет тип файла по его содержимому, а не по заголовку, и хранит фото на постоянном диске (`<DATA_DIR>/photos`, в Docker — `/data/photos`). Открыть фото может только владелец заявки.

**Повторная отправка** того же описания в течение 2 минут возвращает уже созданную заявку — двойное нажатие или повтор после обрыва связи не создают дубль.

Бот честно пишет, что сервис работает в тестовом режиме: заявки хранятся в сервисе и в УК автоматически пока не передаются.

Демо-переменные: `MOCK_AUTO_STATUS_CHANGE=true` меняет статус по времени с пометкой «демо», `DEMO_DUE_MINUTES=3` присылает напоминание через 3 минуты, а нормативный срок в заявке остаётся настоящим.

## Мини-приложение

Экраны: «Квартира» (дом и УК), «Заявки» (кнопка «Подать заявку», список открытых и архив), «Новая заявка», карточка заявки и «Уведомления».

- **Вызвать аварийную службу** — красная кнопка вверху на всех экранах: диспетчер и телефон УК (только из проверенных данных), 104, 112.
- **Уведомления** (колокольчик справа вверху, со счётчиком новых): смена статусов своих заявок, истёкший срок, напоминание, закрытие — и «Соседи уже сообщили»: сколько заявок какой категории подали соседи по дому за неделю. Только количество и категория — без текста, квартир и имён; кнопка «У меня то же — подать заявку» открывает форму с этой категорией. События не хранятся отдельно, а выводятся из заявок (`backend/src/domain/timeline.ts`).
- **Живой таймер срока** в карточке: «осталось 1 ч 20 мин 05 с» и полоска, жёлтая в последней четверти срока, красная после.
- **Хронология заявки**: подана → принята → в работе → срок → напоминание → решена / отозвана.
- **Черновик не пропадает**: текст и категория сохраняются на устройстве и восстанавливаются при следующем открытии (неделю); фото в черновике не хранятся. Загрузка, пустые состояния и ошибки — у каждого экрана свои; светлая и тёмная тема — по теме устройства.

Как оно открывается:
- **Кнопкой «Приложение с заявками» в чате** — это кнопка MAX `open_app`: адрес `https://<домен>/app/` привязан к боту организаторами хакатона. Вход — по подписанным данным MAX.
- **Запасной путь** — если MAX не примет кнопку, бот отправит ссылку с кодом входа на сутки. Код лежит во фрагменте `#t=…`: на сервер в строке запроса он не уходит и в логи не попадает; после входа приложение убирает его из адресной строки.

Разработка: `cd webapp && npm install && npm run dev` (запросы `/api` проксируются на бэкенд `localhost:3000`).

## API мини-приложения

Мини-приложение отдаётся этим же сервером по `/app`, поэтому CORS не включён: API доступен только с того же адреса.

| Запрос | Что делает |
|---|---|
| `POST /api/auth/session` `{ "web_app_data": "<window.WebApp.initData>" }` | проверяет подпись MAX и выдаёт `{ token, expires_in }` на 1 час |
| `POST /api/auth/link` `{ "code": "<код из ссылки бота>" }` | вход по кнопке «Открыть в приложении» |
| `GET /api/me` | квартира, дом и УК (телефоны — только из проверенных данных) |
| `GET /api/requests` | свои заявки с отображаемым статусом и нормативом |
| `GET /api/requests/:id` | одна своя заявка; чужая → `404` |
| `GET /api/notifications` | статусы своих заявок и «соседи уже сообщили» (только категории и количество) |
| `GET /api/catalog` | категории со сроками и основаниями, лимит фото |
| `POST /api/requests/suggest` `{ description }` | категория по описанию (и признак «газ») |
| `POST /api/requests` `{ description, category }` | подать заявку; без квартиры → `409`, газ → `422`, дубль → `200` с той же заявкой |
| `POST /api/requests/:id/photos` (тело — картинка) | добавить фото к своей открытой заявке, до 5 |
| `POST /api/requests/:id/resolve` | «Проблема решена» |
| `GET /api/requests/:id/complaint` | текст жалобы в ГЖИ |
| `GET /api/requests/:id/photos/:photoId` | фото своей заявки (файл с диска); чужое или нескачанное → `404` |
| `POST /api/requests/:id/cancel` | отозвать свою открытую заявку; уже закрытая → `409` |

Все запросы кроме входа — с `Authorization: Bearer <token>`. Пользователь берётся только из токена. Лимит — 60 запросов в минуту на пользователя.

Подпись `web_app_data` проверяется по алгоритму из [документации MAX](https://dev.max.ru/docs/webapps/validation); тест сверяет её с эталонным кодом оттуда. Отличие от ТЗ: MAX передаёт идентификатор в `user.id`, а не `user.user_id`. Ключ сессий — `SESSION_JWT_SECRET`, а если он не задан, ключ производится из токена бота.

- в отслеживаемых файлах нет значений секретов (`git log -p | grep -iE "token|secret|password"` находит только имена переменных и код).

Полная сборка образа в среде разработки не запускалась: там закрыт доступ к Docker Hub. Настоящий замер — журнал сборки на Amvera (тот же `Dockerfile`, чистая сборка) и прогон по инструкции выше на компьютере участника команды.
